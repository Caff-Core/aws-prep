## The idea in plain language

Vehicles come in many types. A delivery van, a sports car, and a bus are all useful, but for different
jobs. You pick the one that suits the load.

**Compute** is the processing power that runs your applications. AWS offers it in many shapes, and
choosing well means matching the shape to the job.

## Amazon EC2

**Amazon Elastic Compute Cloud (Amazon EC2)** provides virtual servers on demand. Each virtual server is
called an **instance**. You choose its size and operating system, and you can start and stop it when you
need to.

Key terms:

- An **Amazon Machine Image (AMI)** is a preconfigured template for launching instances.
- An **instance type** sets the amount of CPU, memory, storage, and networking.
- A **security group** acts as a virtual firewall for instances.

## Scaling and load balancing

### Auto scaling provides elasticity

**Amazon EC2 Auto Scaling** keeps the right number of instances running for the current load. It launches
instances as demand rises and terminates them as it falls, which gives you **elasticity**. It also
replaces unhealthy instances.

### Load balancers

**Elastic Load Balancing** distributes incoming traffic across multiple targets, such as instances in
different Availability Zones. This prevents one server from being overwhelmed and improves availability.
Current types are the Application Load Balancer, Network Load Balancer, and Gateway Load Balancer.

<ImportantConcept>
  Auto scaling changes **how many** servers you run. A load balancer decides **which** server gets
  each request. They are often used together.
</ImportantConcept>

## Simpler ways to run applications

Not everyone wants to manage servers directly.

**AWS Elastic Beanstalk** deploys web applications for you. You upload your code, and it provisions and
configures resources such as instances, load balancing, and scaling. The underlying resources stay
visible in your account.

**Amazon Lightsail** is a simple service with predictable pricing for websites and small applications. It
bundles servers, storage, and networking, and offers prebuilt images such as WordPress.

<CostWarning>
  Stopped or running, resources can still cost money. For example, storage attached to a stopped
  instance may continue to be charged. Elastic Beanstalk has no extra charge of its own, but you pay
  for the resources it creates.
</CostWarning>

<RealWorldExample title="Real-world example: a video platform">
  A Kimberley e-learning company converts lecture videos into several formats. Conversion is heavy
  processing, so it uses compute optimized instances. Its website runs on general purpose instances
  behind a load balancer, with Auto Scaling adding capacity at exam time.
</RealWorldExample>

## What the exam expects

<ExamTip>
  Match the workload word to the family. **Batch processing or transcoding** means compute
  optimized. **In-memory** means memory optimized. **High read and write to local storage** means
  storage optimized. **Elasticity** points to auto scaling, and **distributing traffic** to load
  balancers.
</ExamTip>

## Common misconceptions

- **"Load balancers add servers."** They share traffic. Auto scaling adds servers.
- **"Bigger instances are always better."** Oversized instances cost more than necessary.
- **"Elastic Beanstalk hides everything."** Resources remain visible in your account.
