## The idea in plain language

Shipping containers changed trade. Goods are packed once and move on any ship, train, or truck, because
the box is standard.

A software **container** packages an application with everything it needs, so that it runs the same way
wherever it goes. Running many containers needs coordination, which is called **orchestration**.

**Serverless** goes further. There are still servers, but you do not manage them. You provide the code or
the container, and AWS deals with the rest.

## Running containers

### Amazon ECS

**Amazon Elastic Container Service (Amazon ECS)** is a fully managed AWS service for orchestrating
containers. It can run containers on EC2 instances or on AWS Fargate.

### Amazon EKS

**Amazon Elastic Kubernetes Service (Amazon EKS)** runs **Kubernetes**, a popular open-source container
orchestration system. AWS manages the Kubernetes control plane for you. It suits teams already using
Kubernetes.

## Serverless compute

### AWS Fargate

**AWS Fargate** is serverless compute for containers. You set the CPU and memory for a task, and there
are no clusters of EC2 instances for you to manage.

### AWS Lambda

**AWS Lambda** runs your code without you managing servers. AWS handles scaling and patching. Code is
commonly triggered by events, such as a file arriving in Amazon S3. You are billed for requests and for
the time your code runs.

Lambda's event-driven functions run for up to 15 minutes by default, so they suit short tasks. Lambda's
documentation now also describes other function types for longer-running work.

<ImportantConcept>
  Containers on Fargate suit packaged applications. Lambda suits short pieces of code that react to
  events. In both cases, you do not manage servers.
</ImportantConcept>

<RealWorldExample title="Real-world example: processing receipts">
  A Polokwane accounting firm lets clients upload receipt photos to Amazon S3. Each upload triggers
  a Lambda function that creates a thumbnail, so nothing runs while no receipts arrive. Its main web
  application runs in containers on AWS Fargate, so nobody on the team patches servers.
</RealWorldExample>

## What the exam expects

<ExamTip>
  **Kubernetes** points to Amazon EKS. **Containers without managing servers** points to AWS
  Fargate. **Run code in response to events** points to AWS Lambda. **Full control of the operating
  system** points to Amazon EC2.
</ExamTip>

## Common misconceptions

- **"Serverless means there are no servers."** Servers exist. AWS manages them.
- **"Fargate competes with ECS."** Fargate is a way to run ECS tasks without managing instances.
- **"Containers are virtual machines."** A container packages an application and its dependencies. It is
  not a full virtual server.

## Try it yourself (optional)

You need no AWS account for this, and it costs nothing. Think of a task that happens only occasionally,
such as sending a birthday message. Explain why paying only when the task runs would suit it better than
keeping a server on all year.

## Summary

<LessonSummary>

- Containers package an application with what it needs.
- Amazon ECS and Amazon EKS orchestrate containers. EKS uses Kubernetes.
- AWS Fargate runs containers without servers to manage.
- AWS Lambda runs code in response to events.

</LessonSummary>
