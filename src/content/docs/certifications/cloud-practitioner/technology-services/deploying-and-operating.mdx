## The idea in plain language

There are several ways to order food. You can go to the counter and point, phone in a quick request,
or set up a standing order that arrives the same way each week. Each suits a different need.

AWS works the same way. You can click through a website, type commands, write code that calls AWS, or
describe everything in a file that AWS builds for you.

## Ways to access AWS

### AWS Management Console

The **console** is the web interface for AWS. You sign in and work through screens. It suits learning,
exploring, and one-off tasks.

### AWS Command Line Interface

The **AWS CLI** lets you control AWS by typing commands in a terminal. Commands can be combined into
scripts, so tasks are quicker to repeat than clicking through screens.

### Software development kits

**Software development kits (SDKs)** let applications call AWS services from programming languages such
as Python, Java, and JavaScript.

An **application programming interface (API)** is how software talks to AWS. The CLI and SDKs both use
AWS APIs. This is called **programmatic access**.

### Infrastructure as code

**Infrastructure as code (IaC)** means describing your infrastructure in text files and treating them
like application code. Files can be kept in source control, reviewed, and reused.

**AWS CloudFormation** is the main AWS service for this. You describe resources in a template, and
CloudFormation creates them as a **stack**. Deleting the stack deletes its resources. The AWS Cloud
Development Kit (AWS CDK) lets you define infrastructure using programming languages.

## One-time operations or repeatable processes

A one-time task, such as trying a service, is fine in the console. If you need the same result many
times, use a repeatable process. Manual steps can leave environments inconsistent, because people make
small mistakes or skip steps.

<ImportantConcept>
  If you will do it more than once, or it must be identical every time, automate it. Infrastructure
  as code is the usual answer.
</ImportantConcept>

<RealWorldExample title="Real-world example: identical environments">
  A Pietermaritzburg software team needs test, staging, and production environments that match. It
  writes one CloudFormation template and deploys it three times, in more than one Region if needed.
  When something changes, the team updates the template rather than repeating manual steps.
</RealWorldExample>

**AWS Outposts** supports hybrid setups. It is a fully managed service that runs AWS infrastructure at
your own site, operated by AWS as part of a Region.

## Service models

You may also see three service models. **Infrastructure as a service (IaaS)** gives the most control,
such as Amazon EC2. **Platform as a service (PaaS)** removes the need to manage the underlying operating
system and infrastructure. **Software as a service (SaaS)** is a complete application, such as web email.

## What the exam expects

<ExamTip>
  **Repeatable** or **consistent environments** points to infrastructure as code and AWS
  CloudFormation. **Scripts in a terminal** points to the AWS CLI. **Called from application code**
  points to SDKs. **Cloud connected to on-premises** means hybrid.
</ExamTip>

## Common misconceptions

- **"The console is the only way to use AWS."** Everything you administer there is also available
  programmatically.
- **"Hybrid means two clouds."** Here, it means cloud connected to on-premises infrastructure.
- **"CloudFormation is a compute service."** It provisions resources from a template. You pay for the
  resources it creates.

## Try it yourself (optional)

You need no AWS account for this, and it costs nothing. Write down the steps to set up a new laptop for a
colleague. Decide which steps a script could do. That is the same thinking behind infrastructure as code.

## Summary

<LessonSummary>

- You can use AWS through the console, the AWS CLI, SDKs, or infrastructure as code.
- Repeatable needs call for automation, such as AWS CloudFormation.
- Deployment models are cloud, hybrid, and on-premises.
- AWS Outposts runs AWS infrastructure at your own site.
