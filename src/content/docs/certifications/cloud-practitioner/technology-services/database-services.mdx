## The idea in plain language

A library has different ways to find things. A catalogue with strict columns works for books. A set of
labelled boxes is quick for grabbing something by name. A pile on the front desk holds what people ask
for most.

Databases differ in the same way. No single type suits every job, so AWS offers several.

## Managed databases or databases on Amazon EC2

You can install a database yourself on an Amazon EC2 instance, or use a **managed database** where AWS
does much of the work.

Choose a managed database to reduce operational work. Choose Amazon EC2 when you need full control over
the database and its operating system.

## Relational databases

A **relational database** stores data in tables with rows and columns, and it uses Structured Query
Language (SQL).

**Amazon Relational Database Service (Amazon RDS)** is a managed relational database. It supports engines
including MySQL, PostgreSQL, MariaDB, Oracle Database, Microsoft SQL Server, and IBM Db2.

**Amazon Aurora** is a managed relational engine built for the cloud. It is compatible with MySQL and
PostgreSQL, and its storage grows automatically.

## NoSQL databases

A **NoSQL** database does not use fixed tables in the relational way.

**Amazon DynamoDB** is a serverless, fully managed NoSQL database with single-digit millisecond
performance. It supports key-value and document data. It suits very large scale and simple access
patterns.

## In-memory databases

Memory is much faster than disk. **Amazon ElastiCache** is an in-memory cache, supporting Valkey,
Memcached, and Redis OSS. It stores frequently used data so that applications respond faster.

## Data warehouses

**Amazon Redshift** is a fully managed data warehouse, built for analysing large amounts of data rather
than running day-to-day transactions.

## Database migration tools

**AWS Database Migration Service (AWS DMS)** moves data and can keep replicating changes.

**AWS Schema Conversion Tool (AWS SCT)** converts a database's schema, meaning its structure, from one
engine to another. If you move between different engines, you may need both tools.

<ImportantConcept>AWS SCT converts the **structure**. AWS DMS moves the **data**.</ImportantConcept>

<RealWorldExample title="Real-world example: a mobile game">
  A Durban games studio stores player profiles in Amazon DynamoDB, because millions of players need
  fast lookups by player ID. Its billing system uses Amazon Aurora, because financial records fit
  relational tables. A leaderboard sits in Amazon ElastiCache so that it loads instantly.
</RealWorldExample>

## What the exam expects

<ExamTip>
  **Relational** points to Amazon RDS or Aurora. **NoSQL, key-value, or serverless database** points
  to Amazon DynamoDB. **In-memory or caching** points to Amazon ElastiCache. **Different database
  engine** points to AWS SCT with AWS DMS.
</ExamTip>

## Common misconceptions

- **"Managed means I do nothing."** You still optimise your application and control access.
- **"DynamoDB is relational."** It is NoSQL, and it has no JOIN operator.
- **"AWS DMS converts schemas."** Schema conversion is the role of AWS SCT and DMS Schema Conversion.

## Try it yourself (optional)

You need no AWS account for this, and it costs nothing. Sketch how a small shop might store products,
orders, and customers in three tables. Then consider a shopping cart that only needs fast lookups by
customer ID. Which would suit a relational database, and which a key-value one?

## Summary

<LessonSummary>

- Managed databases shift patching, backups, and scaling to AWS.
- Amazon RDS and Aurora are relational. Amazon DynamoDB is NoSQL.
- Amazon ElastiCache is an in-memory cache, and Amazon Redshift is a data warehouse.
- AWS SCT converts schemas, and AWS DMS moves data.

</LessonSummary>
