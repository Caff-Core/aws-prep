## The idea in plain language

Moving house takes more than a truck. You decide what to keep, what to throw out, what to replace, and
who is responsible for each room.

Moving to the cloud is similar. An organisation needs a plan for its people and processes, a decision
about each application, and the right tools for the move. This lesson covers all three.

## The AWS Cloud Adoption Framework

The **AWS Cloud Adoption Framework (AWS CAF)** is guidance based on AWS experience of helping
organisations transform with the cloud. It identifies the capabilities an organisation needs and helps
it prioritise what to do next.

### Business outcomes

AWS CAF connects cloud adoption to business results. The exam guide names four:

- **Reduced business risk**, through better reliability, performance, and security.
- **Improved environmental, social, and governance (ESG) performance.**
- **Increased revenue**, from new products, customers, and market segments.
- **Increased operational efficiency**, through lower operating costs and better productivity.

### The six perspectives

AWS CAF groups capabilities into six perspectives. Each one represents a different group of
stakeholders.

<ImportantConcept>
  AWS CAF and the Well-Architected Framework are easy to confuse. AWS CAF helps an **organisation**
  adopt the cloud. Well-Architected helps you design and run a **workload**.
</ImportantConcept>

## The seven migration strategies

Each application needs its own decision. AWS Prescriptive Guidance describes seven strategies, often
called the **7 Rs**.

  caption="The seven migration strategies"
  columns={['Strategy', 'What happens', 'Also known as']}
  rows={[
    {

      cells: ['Decommission or archive an application with no business value', '-'],

    { name: 'Retain', cells: ['Keep the application where it is for now', '-'] },
    { name: 'Rehost', cells: ['Move the application without changing it', 'Lift and shift'] },

    },
    {
      name: 'Repurchase',

    },
    {
      name: 'Replatform',
      cells: [
        'Move with some optimisation, such as using a managed database',
        'Lift, tinker, and shift',

      name: 'Refactor',
      cells: ['Redesign the application to use cloud-native features', 'Re-architect'],
    },

/>

Refactoring usually takes the most effort and cost. Rehosting is quicker but does not take full
advantage of the cloud.

<RealWorldExample title="Real-world example: a university moves to AWS">
  A South African university reviews its applications. An old reporting tool nobody uses is
  **retired**. Student email moves to a hosted product, which is **repurchase**. A stable internal
  application is **rehosted** without changes. A research system with strict local dependencies is
  **retained** for now. One organisation can use several strategies at once.
</RealWorldExample>

## Tools that support migration

### AWS Database Migration Service

**AWS Database Migration Service (AWS DMS)** moves data between databases. It can perform a one-time
migration, or it can keep replicating changes so that source and target stay in sync. This replication
means the source database can stay in use during the move.

<ArchitectureDiagram spec={databaseMigration} />

### AWS Application Migration Service

**AWS Application Migration Service** replicates servers to AWS so that they can be launched there,
which supports rehosting. Its documentation now uses the name AWS Transform MGN, so you may see either
name.

### Moving large amounts of data

**AWS DataSync** supports online data transfer. Older material recommends AWS Snowball Edge for
physically shipping data, but AWS now says Snowball Edge is no longer available to new customers.

## What the exam expects

<ExamTip>
  Watch for clue words. **Without changes** means rehost. **Replace with a hosted product** means
  repurchase. **Some optimisation** means replatform. **Redesign** means refactor. **Keep the
  database in use during the move** points to AWS DMS replication.
</ExamTip>

## Common misconceptions

- **"Everything must move to the cloud."** Retain and retire are valid strategies.
- **"There are six Rs."** Older material often lists six. Current AWS guidance lists seven, including
  relocate.
- **"AWS CAF is a technical checklist."** Most of its perspectives concern people and the business, not
  only technology.

## Summary

<LessonSummary>

- AWS CAF helps organisations plan cloud adoption through six perspectives.
- Its outcomes include reduced risk, better ESG performance, more revenue, and greater efficiency.
- The seven migration strategies are retire, retain, rehost, relocate, repurchase, replatform, and
  refactor.
- AWS DMS supports one-time migration and ongoing replication between databases.

</LessonSummary>
